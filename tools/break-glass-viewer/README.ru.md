# Break-Glass Backup Ledger Viewer

> Просмотр и проверка журнала бэкапов, когда сервер недоступен. **Только чтение, офлайн, без backend.**

## Назначение

Когда сервер или база данных лежат (или есть подозрение на взлом), нужен независимый способ доказать: «история бэкапов не была изменена». Этот инструмент решает ровно эту задачу:

- Один HTML-файл. **Без интернета, без backend, без установки.**
- Перетаскиваете файл `backup-ledger.jsonl` (append-only журнал, который пишется при каждом бэкапе).
- Внутри браузера прямо в чистом JavaScript считается SHA-256, что проверяет:
  1. **Связность цепочки (linkage):** в каждой строке `prevHash` должен совпадать с `entryHash` предыдущей строки → обнаруживаются удаления, вставки, перестановки.
  2. **Целостность содержимого (`entryHash`):** если ввести правильный `AUDIT_PEPPER`, инструмент пересчитывает entryHash каждой строки и сравнивает → обнаруживается изменение содержимого.

## Когда использовать

| Ситуация | Зачем |
|---|---|
| Регулярный аудит | Доказать аудитору, что журнал не тронут |
| Сервер лежит / БД мертва | Журнал всё равно проверяется без системы |
| Подозрение на инсайдерскую атаку | Сразу видно удалённые/изменённые строки |
| Перед тем как доверять бэкапу | Сверить sha256 из журнала с реальным дампом перед восстановлением |

## Требования

- Любой браузер (Chrome, Edge, Firefox, Safari)
- Файл `backup-ledger.jsonl` (по умолчанию хранится на offsite-томе отдельно от БД)
- (Опционально) `AUDIT_PEPPER` из `.env` backend для полной проверки entryHash

**Не требуется:**
- Интернет
- Backend / API
- MetaMask / кошелёк
- Права администратора

## Как открыть

### Рекомендуемый способ: на том же томе, что и журнал

```text
USB / NAS offsite/
├── backup-ledger.jsonl
├── backups/
│   ├── BK-20250115-0001.sql
│   └── ...
└── break-glass-viewer/
    └── index.html       ← положить файл сюда
```

1. Скопируйте директорию `tools/break-glass-viewer/` на USB или NAS, где лежит журнал.
2. Откройте `index.html` двойным кликом (запуск через `file://`).
3. Перетащите `backup-ledger.jsonl` в указанную область.
4. (Опционально) Введите `AUDIT_PEPPER` для полной проверки.
5. Смотрите результат: всего записей, статус цепочки, число записей с on-chain якорем.

### Почему offsite, а не на сервере?

Смысл break-glass viewer в том, чтобы **работать, когда сервер не работает**. Если положить его рядом с сервером — упадёт сервер, упадёт и viewer, смысл теряется.

## Чтение результата

| Признак | Значение |
|---|---|
| ✓ «Журнал бэкапов ЦЕЛОСТЕН» + цепочка непрерывна | История цельна (по связности) |
| ⚠ «Цепочка разорвана» | Строка удалена / вставлена / переставлена |
| ⚠ «entryHash не совпадает» | Содержимое строки изменено (или неправильный pepper) |
| Столбец «On-chain якорь» содержит txHash | Манифест успешно заякорен |

> [!IMPORTANT]
> **Работает и без pepper:** проверка связности цепочки не требует секрета. Это и важно — любой аудитор с журналом проверяет всё самостоятельно, без чужих привилегий.
